# 📘 Руководство для администраторов — Matrix VPN Access Bot

Краткое руководство по настройке прав, управлению пользователями, административным командам и отладке бота.

---

## 🔐 1. Управление доступом и AD-группы

Бот работает в **приватных диалогах 1:1**. Каждый пользователь видит только свою историю команд. Доступ проверяется при **каждом сообщении** через LDAP.

| Переменная `.env` | Описание | Пример |
|-------------------|----------|--------|
| `ALLOWED_USERS_GROUP` | AD-группа, члены которой могут использовать `!connect` | `VPN_Users` или полный CN |
| `ADMIN_LOGINS` | Логины администраторов (через запятую). Бот автоматически формирует полные Matrix ID для упоминаний | `a.avdeev,b.belkin` |

> 💡 **Важно:** Если пользователь не состоит в `ALLOWED_USERS_GROUP`, бот отклонит команду и отправит уведомление администраторам в целевую комнату с `@упоминаниями`.

---

## 🏷️ 2. Обязательные атрибуты AD

Для корректного определения компьютера пользователя в сети требуется заполнить атрибут в Active Directory:

| Атрибут | Формат | Назначение |
|---------|--------|------------|
| `msDS-PrimaryComputer` | Distinguished Name (DN) компьютера | `CN=OF-IT777,OU=Computers,DC=st-oil,DC=local` |

**Как это работает:**

1. Бот извлекает `CN` из DN (`OF-IT777`)
2. Формирует DNS-имя: `OF-IT777.st-oil.local`
3. Использует его для добавления в MikroTik Firewall

⚠️ Если атрибут пуст, содержит `None` или невалидные символы → доступ блокируется, админы получают алерт.

---

## 🛠️ 3. Административные команды

Доступны только пользователям из `ADMIN_LOGINS`. Префикс: `!`

| Команда | Описание |
|---------|----------|
| `!admin_disconnect <login>` | Принудительно отключить пользователя и удалить IP из MikroTik |
| `!check_user <login>` | Проверить членство в группе и значение `msDS-PrimaryComputer` |
| `!history [N]` | Показать последние N подключений (по умолчанию 20) |
| `!log [N]` | Показать последние N строк лога (по умолчанию 20) |
| `!pending_list` | Список пользователей, ожидающих настройки или отклонённых по правам |
| `!pending_clear` | Очистить список ожидающих |
| `!rule_enable [comment]` | Включить правила FW по комментарию |
| `!rule_disable [comment]` | Отключить правила FW по комментарию |
| `!restart_service` | Перезапустить службу на удалённой Windows-машине (через WinRM) |

## 🔔 4. Уведомления администраторам

Бот автоматически отправляет алерты в целевую комнату (`MATRIX_ROOM_ID`) в формате:

```
⚠️ @a.avdeev:matrix.domain.local @b.belkin:matrix.domain.local
Пользователь ivanov попытался подключиться, но msDS-PrimaryComputer пуст.
```

**Триггеры уведомлений:**

- Пользователь не в `ALLOWED_USERS_GROUP`
- Атрибут `msDS-PrimaryComputer` отсутствует или невалиден
- Критические ошибки LDAP/MikroTik/State Manager

## 📋 5. Типовые задачи администратора

### ✅ Добавить пользователя в разрешённую группу

1. Откройте **Active Directory Users and Computers**
2. Найдите группу `VPN_Users` → **Properties** → **Members** → **Add**
3. Введите логин пользователя → **Check Names** → **OK**

### 🔍 Проверить атрибут `msDS-PrimaryComputer`

```powershell
Get-ADUser -Identity a.avdeev -Properties msDS-PrimaryComputer | Format-List msDS-PrimaryComputer
```

Если поле пустое → заполните его через ADUC или PowerShell:

```powershell
Set-ADUser -Identity a.avdeev -Replace @{msDS-PrimaryComputer="CN=OF-AVDEEV,OU=Computers,DC=st-oil,DC=local"}
```

### 🚫 Принудительно отключить пользователя

```text
!admin_disconnect a.avdeev
```

### 📜 Проверить последние подключения

```text
!history 10
```

Вывод покажет время, логин, IP и длительность с учётом настроенного часового пояса.

## 🐛 6. Отладка и логирование

### Логи

- Файл: `./logs/bot.log` (на хосте)
- Просмотр в реальном времени:

  ```bash
  make logs
  # или
  tail -f logs/bot.log
  ```

- Ротация настраивается в `.env`: `LOG_MAX_BYTES`, `LOG_BACKUP_COUNT`, `LOG_LEVEL`

### Состояние и ожидающие пользователи

| Файл | Назначение | Ручное управление |
|------|------------|-------------------|
| `data/connection_state.json` | Активные сессии и история | Не рекомендуется. Используйте `!admin_disconnect` или очистку через бота |
| `data/pending_users.json` | Пользователи, отклонённые по правам или атрибутам | Можно редактировать вручную, затем `make restart` |

> ⚠️ Оба файла монтируются в Docker. При удалении контейнера данные **сохраняются**.

### Очистка "зависших" сессий

Если пользователь отображается подключённым, но реально отключился:

```bash
# Сброс состояния (осторожно: сбросит историю активных сессий)
rm data/connection_state.json
make restart
```

## 🔒 7. Безопасность и рекомендации

- ✅ Сервисная учётная запись LDAP должна иметь права **только на чтение** `memberOf` и `msDS-PrimaryComputer`
- ✅ SSH доступ к MikroTik ограничьте по IP (разрешите только хост бота)
- ✅ Никогда не коммитьте `.env` в Git (файл в `.gitignore`)
- ✅ Используйте `ALLOWED_USERS_GROUP` для минимизации blast radius
- ✅ Приватные диалоги Matrix исключают утечку истории команд между сотрудниками
